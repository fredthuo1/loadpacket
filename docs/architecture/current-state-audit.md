# Repository architecture audit

LP-PROD-001 follow-up: [current infrastructure evidence](current-infrastructure-evidence.md), [backup evidence](current-backup-evidence.md), [privilege/schema inventory](database-compatibility-inventory.md), [ACK traces](current-write-paths.md) and [health model](current-health-model.md) now provide the repository-only baseline. Provider facts remain unknown by the user's chosen scope. Extraction currently persists status rather than a durable extraction-result record; Finance import detail reads can fail after a committed mutation. The Finance UPDATE trigger compares every non-status field, but is not a DELETE guard. See [new report](lp-prod-001-report.md); no readiness gate changed to PASS.

Reviewed 2026-10-01 against the working tree, including uncommitted earlier work. Source inspection only; no provider console, live database, customer records, credentials or production endpoint inspection. IMPLEMENTED means code exists, not that a production deployment/configuration was certified. PARTIALLY_IMPLEMENTED means a relevant safeguard exists but the requested complete capability does not. MISSING means not found in reviewed source/configuration; UNKNOWN_REQUIRES_VERIFICATION covers external settings.

The previous [LP-PROD-01 hosting report](../production/lp-prod-01-report.md) addresses a different, single-instance scope. This package supersedes its production-readiness interpretation without rewriting its historical evidence. User-reported Render operation and Android login/load acceptance are useful operational context, not regional durability evidence.

## Capability inventory

1. **Authentication — IMPLEMENTED.** [Token verifier](../../apps/api/src/auth/supabase-token-verifier.ts) verifies issuer/audience/expiry/subject and ES256/RS256 JWKS; legacy HS256 uses Supabase `getUser`. [Auth service](../../apps/api/src/auth/auth.service.ts) maps the verified subject to active app User/Driver. External Auth continuity/backup: UNKNOWN_REQUIRES_VERIFICATION.
2. **Authorization — IMPLEMENTED.** Global [auth module](../../apps/api/src/auth/auth.module.ts) installs authentication, invitation and deny-by-default role guards. Public routes require their own explicit grant/health policy. Server authorization, not hidden controls, is authoritative.
3. **Tenant isolation — PARTIALLY_IMPLEMENTED.** Service filters derive organization from authenticated User; all tenant models have organizationId. Composite FKs exist on newer features, not all legacy edges. Supabase Data API denial is not API-runtime tenant RLS. See [model-by-model inventory](tenant-model-inventory.md).
4. **API — IMPLEMENTED.** [App module](../../apps/api/src/app.module.ts) is a modular monolith; [bootstrap](../../apps/api/src/main.ts) applies validation whitelist, errors, CORS, no-store and `/api/v1`. No write-readiness middleware or operation-outcome envelope exists.
5. **Database — PARTIALLY_IMPLEMENTED.** [Prisma service](../../apps/api/src/database/prisma.service.ts) uses PrismaPg, pool max 5 and timeouts. PostgreSQL/Prisma 7.10.0; actual topology, synchronous commit, backups, runtime role and TLS mode UNKNOWN_REQUIRES_VERIFICATION. One configured connection does not prove regional RPO 0.
6. **Schema — IMPLEMENTED.** [Schema](../../apps/api/prisma/schema.prisma) includes UUIDs, Decimal(12,2), JSON/Bytes, composite tenant keys, enums and evidence history. HistoricalLoadRecord lacks an explicit currency column; Finance is currently USD-oriented. Some broad cascades require retention review.
7. **Migrations — IMPLEMENTED.** [Migrations](../../apps/api/prisma/migrations) contains 17 timestamped directories, including PL/pgSQL triggers, RLS setup, indexes and constraints. Applied production state UNKNOWN_REQUIRES_VERIFICATION; no migration/status command was run in this audit.
8. **Storage — PARTIALLY_IMPLEMENTED.** [DocumentStorage](../../apps/api/src/documents/document-storage.ts) abstracts put/read/removeUncommitted. Local adapter uses private paths and exclusive `wx`; production absolute root is mandatory. No cross-region storage, durable receipts, explicit fsync contract or multi-site routing.
9. **Versioning — PARTIALLY_IMPLEMENTED.** DocumentVersion tracks tenant, version, checksum, size, MIME, uploader and relative key; vault creates new versions. Database-wide update/delete prevention for DocumentVersion is not established. Storage key immutability alone does not freeze metadata.
10. **Signatures — PARTIALLY_IMPLEMENTED.** [Service](../../apps/api/src/documents/signatures.service.ts) binds exact version/document/load/tenant, signer role/name, actor, checksum and idempotency key; [migration](../../apps/api/prisma/migrations/20260928090000_document_signatures/migration.sql) rejects UPDATE and adds composite FKs. Document checksum is available through version, not snapshotted on signature; bytes remain local. DELETE/cascade is not prevented by the UPDATE trigger.
11. **Finance — PARTIALLY_IMPLEMENTED.** [Service](../../apps/api/src/finance/finance.service.ts), [imports](../../apps/api/src/finance/finance-import.service.ts) and migrations provide decimal amounts, currency, provenance, corrections, reversal and audit events. Trigger protects selected amounts/identity fields, not universal append-only history. Reports/payroll/tax are preparation, not a general ledger or filing service.
12. **Load lifecycle — IMPLEMENTED.** [Loads](../../apps/api/src/loads/loads.service.ts), readiness policy, Driver service and accounts receivable enforce status transitions with transactions/row locks. Creation and mutations lack a uniform request-key replay contract; see [mutation audit](mutation-audit.md).
13. **Driver lifecycle — IMPLEMENTED.** Active mapping, assignment checks, invitation onboarding and race checks exist in [driver services](../../apps/api/src/drivers). Production identity-provider settings are external.
14. **Mobile offline — PARTIALLY_IMPLEMENTED.** [Client](../../apps/mobile/src/api/client.ts) has request deadlines, controlled errors, one refresh and account-switch guards. [SecureStore](../../apps/mobile/src/auth/supabase.ts) persists sessions. Upload retry and signature draft are memory-bound; no durable operation queue/restart recovery was found.
15. **Background jobs — MISSING.** `apps/worker` has no implementation. Extraction, invoice generation and invitation provider calls run in request flows; not a durable worker system.
16. **Queues — MISSING.** No transactional outbox, durable inbox, queue broker or worker lease implementation found. Payment readiness “queue” is a query/UI concept, not message delivery.
17. **Caching — PARTIALLY_IMPLEMENTED.** JWKS cache and mobile SDK/customer state exist; no distributed business cache. API private no-store is present. Framework/provider caches need deployment verification.
18. **Email/invitations — PARTIALLY_IMPLEMENTED.** [Invitation service](../../apps/api/src/drivers/driver-invitation.service.ts) calls provider inside transaction and compensates uncertain outcomes cautiously. Resend has 60-second throttle. No durable send intent/outbox; provider success and DB commit are not atomic.
19. **RevenueCat — IMPLEMENTED.** [Subscription service](../../apps/mobile/src/subscriptions/service.ts) uses stable app User.id and refreshes authoritative entitlement; errors lock Finder while free operations remain. [Config](../../apps/mobile/src/subscriptions/config.ts) permits Test Store only when native adapter supplies `__DEV__`. Native Test Store/store purchase acceptance remains external and unproven by mocks.
20. **Logging — PARTIALLY_IMPLEMENTED.** Sanitized errors and selected actor/action logs exist. No centralized redaction/correlation/retention pipeline found; external access-log policy UNKNOWN_REQUIRES_VERIFICATION.
21. **Health — PARTIALLY_IMPLEMENTED.** [Controller](../../apps/api/src/app.controller.ts) has `/health` and `/health/database` SELECT 1 only. No `/health/live`, `/health/ready`, `/health/write-ready` or durable commit probe.
22. **Monitoring — MISSING.** No application OTel/metrics/paging implementation found; provider dashboards/alerts UNKNOWN_REQUIRES_VERIFICATION.
23. **Deployment — PARTIALLY_IMPLEMENTED.** [Reference guide](../production/deployment.md) and operator checklist exist. Hosted operation is user-reported; region redundancy, edge failover and change-control evidence are absent from repository.
24. **Docker — IMPLEMENTED.** [API](../../infrastructure/docker/api.Dockerfile) and [web](../../infrastructure/docker/web.Dockerfile) preserve Node 24, pnpm 12.3.4, non-root runtime and explicit client build config. Image/scanning/reproducibility evidence is not refreshed in this audit.
25. **Terraform — MISSING.** `infrastructure/terraform` is empty; no provisioned modules/state/plan pipeline found. Directory names are not infrastructure.
26. **Environment — PARTIALLY_IMPLEMENTED.** Example variable names, public/server split and production CORS/storage guards exist. No environment values were read. Environment/account isolation and rotation are UNKNOWN_REQUIRES_VERIFICATION.
27. **CI/CD — MISSING.** Local scripts exist, `.github` workflows absent. No immutable artifact promotion, canary or protected migration job found.
28. **Regression — IMPLEMENTED.** [Gate](../../scripts/release-gate.cjs) and [isolated wrapper](../../scripts/finance-regression.ps1) cover type/lint/unit/HTTP/browser/mobile/security and isolated DB integrity. Historical normal gate: 24/24 on 2026-09-30 UTC; subsequent mobile change: 33 tests passed. These are prior evidence, not reruns or chaos evidence.
29. **Backups — UNKNOWN_REQUIRES_VERIFICATION.** Operator guidance exists; no automated cross-account immutable backup/restore evidence found. Do not infer a provider plan or retention window.
30. **Disaster recovery — MISSING.** No exercised regional recovery orchestration or timed full restoration report found. Existing deployment notes are insufficient for RPO 0.
31. **Rate limiting — PARTIALLY_IMPLEMENTED.** Invitation resend cooldown exists. General tenant/IP/request/upload quotas are absent; edge controls UNKNOWN_REQUIRES_VERIFICATION.
32. **Upload security — PARTIALLY_IMPLEMENTED.** Size/MIME guards, SHA-256, safe storage keys, vault magic-byte checks and signature PNG validation exist. RateCon/Driver uploads do not share equivalent magic-byte validation; malware quarantine/scanning is missing. Parser sandbox/resource controls need hardening.
33. **Audit — PARTIALLY_IMPLEMENTED.** [Load events](../../apps/api/src/load-events/load-events.service.ts), Finance audit and operational logs cover selected actions. No universal append-only audit, tamper archive or consistent trace ID; some audit writes are outside business transactions.
34. **Idempotency — PARTIALLY_IMPLEMENTED.** Payments, Finance, signatures and vault uploads have feature-specific keys/uniqueness. State guards alone do not replay results for lost responses. No generic durable registry/provider inbox.
35. **Transactions — PARTIALLY_IMPLEMENTED.** Multi-row workflows use transactions, row locks and advisory locks. Storage/provider I/O can occur inside DB transactions; no atomic external commit exists. Retried transaction callbacks must not duplicate external effects.

## Concrete risk register

- P0-DUR: successful local storage write plus SQL commit can lose evidence on volume/region failure. No tested commit-domain contract.
- P0-TEN: ID-only legacy relationships admit inconsistent cross-tenant edges if a service regression bypasses checks; see complete schema inventory. This is a safeguard gap, not a claim of demonstrated public exploit.
- P0-ACK: timeout after commit cannot safely be represented as “No changes were accepted.” Current clients do not persist reconciliable operation IDs for all mutations.
- P0-UP: inconsistent upload validation and no malware quarantine permit untrusted parser input before a uniform security boundary.
- P0-EXT: email/provider side effects in DB transaction can escape rollback. Files must remain on ambiguous commit until reconciled.
- P0-REC: no independent backup evidence, key recovery drill, write fencing, regional failure test, paging or tested support procedure.
- P1-MOD: `AgreementAcceptance.providerEnvelopeId` is provider-specific core data; isolate in an integration mapping in a later backward-compatible ticket. No refactor in this audit.
- P1-CLARITY: duplicate draft files such as `payment-readiness.controller (2).ts` warrant inventory cleanup later; do not assume they are mounted routes.

No current architecture can be certified for real-customer RPO-0 production from repository evidence alone. See [release gates](release-gates.md) for exact unresolved evidence.
